Operating model

From ambiguity to an operating product.

I use the same underlying pattern whether the output is a service flow, dashboard, learning product or enterprise tool.

01

Frame

Clarify the user, problem, decision, constraints and success criteria before choosing a solution.

02

Model

Map process, rules, states, data, dependencies and metrics until the problem becomes inspectable.

03

Build

Create the flow, dashboard, service or prototype that makes the model usable by real people.

04

Validate

Challenge formulas, edge cases, UX, source interpretation, assumptions and causal language.

05

Scale

Define ownership, governance, support, adoption, documentation and the next product backlog.
